# 🚀 Automated API Testing Project (Rest Assured + JUnit 5)

Проект по автоматизации тестирования REST API с использованием библиотеки **Rest Assured** и тестового фреймворка **JUnit 5**. В качестве тестового стенда используется открытый сервис [ReqRes.in](https://reqres.in).

---

## 🛠️ Стек технологий и инструменты

* **Язык программирования:** Java 11 / 17
* **Тестирование API:** Rest Assured (v5.5.0)
* **Тестовый фреймворк:** JUnit 5 (v5.11.0)
* **Сериализация/Десериализация:** Google Gson (v2.11.0)
* **Инструменты оптимизации кода:** Project Lombok (v1.18.34)
* **Сборщик проектов:** Maven
* **Отчетность:** Allure Report

---

## 🏗️ Архитектура и паттерны проекта

Проект построен с разделением логики на независимые слои, что обеспечивает масштабируемость и простоту поддержки кодовой базы:

* **`TestBase`** — базовая конфигурация тестов, содержащая общую спецификацию запросов (`RequestSpecification`), настройки базового URI, Content-Type (JSON) и подключение лог-фильтров.
* **Routes / Endpoints (`RoutesPatern`)** — паттерн изоляции путей. Все эндпоинты вынесены в отдельные строковые константы. В тестах пути подставляются динамически (используются Query и Path параметры).
* **Модели данных (POJO)** — использование Java-классов (`UserRequest`, `UserResponse`) для автоматического преобразования Java-объектов в JSON (Сериализация) и обратно (Десериализация) силами библиотеки **Gson**.
* **Lombok (`@Data`, `@AllArgsConstructor`)** — автоматическая генерация геттеров, сеттеров и конструкторов во время компиляции для избавления от шаблонного (boilerplate) кода.

## 📋 Покрытые тест-кейсы (CRUD-операции)

1. **GET (Получение списка пользователей):** Проверка статус-кода `200`, валидация структуры JSON (номер страницы, проверка массива на наполненность и валидация формата email).
2. **POST (Создание пользователя):** Отправка POJO-модели запроса, проверка статус-кода `201`, десериализация ответа и валидация динамических полей (`id`, `createdAt`).
3. **PUT (Обновление данных):** Использование динамического Path-параметра `{id}`, отправка измененных данных, проверка статус-кода `200` и валидация даты изменения (`updatedAt`).
4. **DELETE (Удаление пользователя):** Проверка успешного статус-кода `204` и валидация абсолютно пустого тела ответа (`emptyString`).
5. **POST Negative (Валидация ошибок):** Тестирование некорректного запроса на регистрацию без пароля, проверка статус-кода `400` и сверка текста ошибки бэкенда.

## ⚙️ Инструкция по запуску

Для сборки проекта и запуска автотестов выполните команду в корневой папке проекта:

```bash
mvn clean test
```

### 📊 Генерация отчета Allure

После завершения тестов технические результаты сохраняются в папку `allure-results`. Чтобы скомпилировать их в интерактивный веб-отчет, используйте плагин Allure:

```bash
mvn allure:serve
```
*После выполнения команды локальный сервер автоматически запустится и откроет отчет в браузере по умолчанию.*
